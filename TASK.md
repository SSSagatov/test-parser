## 1. Цель проекта

Разработать Python-приложение, которое через официальный **goszakup.kz GraphQL API V3** получает лоты по следующим условиям:

| Параметр | Значение |
|---|---|
| Источник | Государственные закупки Республики Казахстан |
| API | GraphQL V3 |
| Регион | Павлодарская область |
| Тип закупок | Только государственные закупки |
| Самрук-Казына | Исключить |
| Митворк | Исключить |
| ФСМС | Исключить |
| Даты | Сегодня + завтра |
| Часовой пояс | Asia/Almaty, UTC+5 |
| Статус | Открытый приём заявок |
| Формат результата | JSON + Excel |
| Авторизация | API-токен из `.env` |

Главное требование: **не скачивать все лоты Казахстана для последующей фильтрации**.

Используй серверные фильтры GraphQL API V3 настолько полно, насколько это позволяет реальная схема API.

Не придумывай неподдерживаемые параметры.

### Логика периода

Для первой версии приложения принять следующую бизнес-логику:

Лот подходит, если период приёма заявок пересекается с календарным интервалом от 00:00 сегодняшнего дня до 00:00 послезавтрашнего дня, в часовом поясе Asia/Almaty.

При этом приём заявок должен быть открыт на момент запуска приложения.

Пример:

Дата запуска: 15.10.2026.

Диапазон календарного поиска:

- Начало: 15.10.2026 00:00
- Конец: 17.10.2026 00:00, не включая эту границу

Текущая активность:

`submission_start <= now < submission_end`

Пересечение с периодом:

`submission_start < window_end AND submission_end > window_start`

Проверить соответствие официальным правилам статусов и граничных дат API.

Вынести режим фильтрации дат в конфигурацию, чтобы впоследствии можно было выбирать:

- `active_now` — приём заявок открыт прямо сейчас;
- `starts_in_window` — приём начинается сегодня или завтра;
- `ends_in_window` — приём заканчивается сегодня или завтра;
- `overlaps_window` — период приёма пересекается с сегодняшним или завтрашним днём.

По умолчанию использовать `active_now` вместе с проверкой пересечения с двухдневным окном.

## 2. Исследование официального GraphQL API V3

Прежде чем писать бизнес-логику, исследуй официальную документацию.

Основная документация:

https://ows.goszakup.gov.kz/help/v3/schema/

Предполагаемый GraphQL endpoint:

https://ows.goszakup.gov.kz/v3/graphql

Обязательно проверь фактический endpoint и формат авторизации по официальной документации.

Изучи:

1. Корневые GraphQL-запросы для объявлений и лотов.
2. `TrdBuy` и связанные объекты.
3. `Lots` и связанные объекты.
4. `TrdBuyFiltersInput`.
5. `LotsFiltersInput`.
6. Фильтры `kato` и `strKato`.
7. Фильтры статусов объявлений.
8. Даты начала и окончания приёма заявок.
9. Связь объявления с лотами.
10. Пагинацию `limit` / `after`, если она подтверждена схемой.
11. Возможность получать технические спецификации.
12. Формирование официальных ссылок на лоты.
13. Ограничения API и допустимую частоту запросов.

**Нельзя считать поля или фильтры существующими без подтверждения схемой.**

Особое внимание удели тому, к какому объекту относится `kato`: месту поставки, адресу заказчика или другому географическому признаку.

Если серверный фильтр `strKato` не соответствует месту поставки, реализуй дополнительную проверку географии на уровне лота.

Если API не поддерживает серверную фильтрацию по датам приёма заявок, применяй её после максимально узкого запроса по доступным фильтрам.

Не подменяй дату приёма заявок датой публикации объявления.

## 3. Авторизация

Токен хранится исключительно локально.

Создай `.env.example`:

```dotenv
GOSZAKUP_API_TOKEN=YOUR_API_TOKEN

GOSZAKUP_GRAPHQL_URL=https://ows.goszakup.gov.kz/v3/graphql

TARGET_REGION=Pavlodar
TIMEZONE=Asia/Almaty

DATE_MODE=active_now
WINDOW_DAYS=2

PAGE_SIZE=100
REQUEST_TIMEOUT=30
MAX_RETRIES=5
MAX_CONCURRENT_REQUESTS=3

OUTPUT_DIR=output
```

Требования:

- Использовать `pydantic-settings` или `python-dotenv`.
- Не хранить токен в коде.
- Не записывать токен в логи.
- Не отправлять токен сторонним сервисам.
- Добавить `.env` в `.gitignore`.
- Проверять наличие токена при запуске.
- Обрабатывать ошибки авторизации.

Не запрашивай токен у пользователя в переписке.

## 4. Оптимизация GraphQL-запросов

Это один из самых важных разделов.

### Требование

**Не выгружать миллионы лотов, если можно получить подходящие записи через серверную фильтрацию.**

Реализовать стратегию:

**Этап A — получение объявлений**

Запрашивать объявления с максимально узкими поддерживаемыми фильтрами:

- Павлодарская область;
- официальный статус приёма заявок;
- другие подходящие серверные ограничения, подтверждённые схемой.

Если даты нельзя фильтровать на сервере, проверять их после получения объявлений.

**Этап B — проверка периода**

Оставлять объявления, удовлетворяющие заданному режиму дат.

**Этап C — получение лотов**

Получать только лоты отобранных объявлений.

**Этап D — проверка места поставки**

Проверять регион каждого лота по официальным географическим данным.

**Этап E — получение подробностей**

Запрашивать полную информацию только по подходящим лотам.

### Дополнительные требования

- Не выполнять лишние GraphQL-запросы.
- Не запрашивать полные вложенные объекты на этапе первичного поиска.
- Использовать минимальный набор полей для фильтрации.
- Применять пагинацию.
- Исключать повторную обработку ID.
- Использовать ограниченный параллелизм.
- Кэшировать неизменяемые справочники.
- Соблюдать ограничения API.

Если API не позволяет достаточно узко фильтровать данные, явно объяснить ограничение.

Не утверждать, что серверная фильтрация работает, пока она не проверена реальным запросом.

## 6. Полнота данных лота

Для каждого подходящего лота получить все доступные через API поля.

В том числе:

**Идентификация:** ID, номер лота, ID объявления, наименование, описание, предмет закупки, способ закупки, статус.

**Финансы:** плановая сумма, цена за единицу, количество, единица измерения, валюта, НДС при наличии.

**Организации:** заказчик, БИН заказчика, организатор, БИН организатора.

**Даты:** публикация, начало приёма, окончание приёма, обновление, сроки поставки.

**География:** регион, населённый пункт, адрес поставки, КАТО.

**Документы:** техническая спецификация, доступные приложения и документы.

**Ссылки:** прямая официальная ссылка на лот и объявление.

Сохранять исходный GraphQL JSON без потери полей.

Если часть информации недоступна, оставлять `null`, а не придумывать значения.

`output/pavlodar_lots_YYYY-MM-DD.xlsx`

Все ключевые поля на русском языке.

Максимально полная плоская структура исходных данных.

Технические спецификации и другие доступные документы.

Неоднозначные лоты с причинами исключения из подтверждённой выборки.

Количество обработанных объявлений, лотов, подходящих записей, дубликатов, ошибок и общая сумма.

### `Metadata`

Дата выгрузки, часовой пояс, версия API, применённые фильтры, количество запросов, полнота выборки.

Требования к Excel:

- автофильтры;

- корректные даты;
- удобная ширина столбцов;
